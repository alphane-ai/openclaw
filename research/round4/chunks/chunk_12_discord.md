2) 模块要点
- 配置与基础服务：`accounts.ts` 提供 token/启用状态的统一解析，`client.ts` + `createDiscordRestClient` 将 carbon request client 与重试策略打包，`api.ts` 封装 Discord REST 调用的 retry/429 逻辑并由 `guilds.ts`/`directory-live.ts`/`audit.ts` 复用，`chunk.ts` 在 outbound reply 里守住字符/行数限制并兼顾 code fence 语义。
- UI 与交互：`components.ts` 定义 Discord 交互块（buttons、select、modal）与 payload 解析，`components-registry.ts` 用 TTL 缓存组件/模态条目，`monitor/agent-components.ts` 和 `monitor/exec-approvals.ts` 组合 Carbon 组件、模态、按钮构造 agent 选择、pinpoint 交互，执行审批、pairing 通知等场景。
- 网关与存在感知：`monitor/gateway-plugin.ts` 根据 config 拆解 intents、代理并创建 `GatewayPlugin`，`monitor/gateway-registry.ts` 让 exec 组件/agent 工具访问 `registerGateway`，`monitor.gateway.ts` 和 `gateway-logging.ts` 负责 gateway 生命周期监控与日志，`presence.ts`/`presence-cache.ts` 处理 presence 更新。
- 监听与消息处理：`monitor.ts` 是入口，负责加载 config、解析 allowlists（`monitor/allow-list.ts`）、deploy native slash commands（`monitor/native-command.ts`）、注册 listener/exec approvals/gateway logging，`monitor/listeners.ts` 实现 message/reaction/presence 监听器并将事件转为 auto-reply/系统事件。
- 消息预检与处理：`monitor/message-handler.ts` 通过 debouncer 保证吞吐，`message-handler.preflight.ts` 做 allowlist、mention、pairing、system event、thread、history、access gating 校验，`message-handler.process.ts` 负责 media、路由、session、ack reaction、typing、`dispatchInboundMessage` 以及 `deliverDiscordReply`，`message-utils.ts` 提供 channel id、text/media 解析，`format.ts` 管理标签/时间格式。
- Native Slash Command & exec 交互：`monitor/native-command.ts` 构造 Carbon `Command`（参数转 Auto-reply arg、chunk 模式、typing/媒体限制），`provider.skill-dedupe.test.ts`/`provider.proxy.test.ts` 保证 command 限制与代理情形安全。 `monitor/exec-approvals.ts` 将 exec approval 请求渲染为 Discord buttons、从 `infra/exec-approvals` 获取 metadata 后回写决策。

3) 关键调用链
- `monitorDiscordProvider` → load config/token → resolve guild/channel/user allowlists → deploy native commands → instantiate `@buape/carbon` client（listeners、components、gateway plugin）→ register gateway/presence logging → `waitForDiscordGatewayStop` 负责 clean shutdown。
- `DiscordMessageListener` → `createDiscordMessageHandler`（带 `createInboundDebouncer`）→ `preflightDiscordMessage`（allowlist/mention/DM policy/channel config/thread/PluralKit/pairing/system event）→ `processDiscordMessage`（media+text->route->session->history->typing/ack reaction->`dispatchInboundMessage` + `deliverDiscordReply` + ack cleanup + history trimming）。
- Reaction/presence flows：`DiscordReactionListener`/`PresenceListener` → `handleDiscordReactionEvent`/`setPresence` → `resolveAgentRoute` + `enqueueSystemEvent` or `presence-cache` updates，`shouldEmitDiscordReactionNotification` 控制通知 mode。
- Native command pipeline：`listNativeCommandSpecsForConfig` + `createDiscordNativeCommand` → Carbon command registration → interaction handler 建立 reply context（`finalizeInboundContext`、`deliverDiscordReply`、chunking）→ `monitor/tool-result.*` 测试确保 mention patterns & status replies。
- UI interactions：Agent component buttons/selects/modals → `components-registry` TTL lookups → `dispatchReplyWithBufferedBlockDispatcher`、`recordInboundSession`、`sendTyping`、`resolveReplyContext` 等共同完成 moderator 交互与 pairing 回复。

4) 风险
- Discord 本身的 100 个 slash command 限制使 `nativeEnabled` + `nativeSkillsEnabled` 配置可能触发 `commandSpecs` 回退，需留意 `provider.skill-dedupe.test.ts` 对此的 guardrail；配置过多仍可能导致部署失败或遗漏可用命令。
- allowlist/guild/channel schema 复杂（`monitor/allow-list.ts` 使用 slug、ID、channel-parent fallback），配置或同步不当会无意中把合法频道/用户阻断，在 `preflightDiscordMessage` 的 mention gating 之后仍可能把消息销毁。
- 连接/令牌失效、缺少 permissions 或 gateway 代理配置异常（`audit.ts` / `fetchDiscord` + `gateway-logging.ts`）会导致用户反馈不明显；`monitor/provider.proxy.test.ts` 需要保持更新。
- 组件/模态的 TTL 缓存（`components-registry.ts`）与 exec approval 超时时间必须和 Discord 交互时间保持一致，否则点击/模态会“找不到” entry，导致交互失败。
- 广播到 `dispatchInboundMessage` 依赖 `auto-reply`、`routing`、`channels/session` 等模块，任何 upstream 的 session store、ack reaction、chunk config 错配都可能导致回覆丢失或重复。

5) 与已研究模块关联
- 与 auto-reply (chunk 08-11) 直接共用 `chunk.ts`、`dispatchInboundMessage`、`commands-registry`、`reply-dispatcher`、`envelope`、`history`、`pairing` 等基础构建块；message handler 依赖 `resolveAgentRoute` 和 `buildAgentSessionKey`（routing/session 研究，参见 earlier channel docs）。
- 频道/命令 gating 与 `channels/allowlist-match`、`channels/command-gating`、`channels/mention-gating`、`channels/session`/`session-key` 研究内容紧密耦合，Discord 特定 allowlist 只是默认策略的一个变体。
- `directory-live.ts` 让 Discord 频道/成员出现在 `channels/plugins/directory`（chunk_14_slack 已研究的 channel directory 实现）里的“实时搜索”结果中，所有目录插件共用 `DirectoryConfigParams`。
- 所有附件/媒体逻辑调用 `media/fetch`、`media/store`，与 earlier `auto-reply` 研究中处理上传的流程一致；`infra/exec-approvals`、`gateway`、`runtime` 也在 Discord 模块中发挥相同职责。
